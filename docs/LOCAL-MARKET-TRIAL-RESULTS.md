# Local market trial — October 1, 2026

**Completed: 1:08–1:18 p.m. Eastern (17:08–17:18 UTC). Cloud collection stayed paused.** The user selected local measurement because the $0 target did not permit assuming that upstream traffic qualified for Google's free outbound transfer. The ten-minute trial ran the real collector against public Hypixel data, SQLite on this PC, and the actual browser interface on loopback. It made **zero Google collector operations**. This does not describe the earlier private cloud preparation or the cost of retained cloud resources.

The process stopped at **17:18:00.021 UTC**, exited successfully, and stored a durable stop at 17:18:00.012. Re-running the expired plan refused before network access. Both browser views independently displayed “Updates paused to protect the free allowance,” with their actual data timestamps. A read-only cloud check at **17:19:49 UTC** confirmed **Scheduler PAUSED / no public API invoker**. The unused cloud trial window ended at 17:12; temporary shutdown permissions expired at 17:15. Neither was extended. The main website, authentication, saved user data and Apps Script account/email handling were left in their existing state; market-dependent comparisons and alerts remain unavailable when data is stale or paused.

## What the results support

1. **Keep cloud collection and production market polling paused for the $0 target.** This was the user's selected mode, and it remains applied. The local trial is also finished; no automatically recurring local run was installed.
2. **120 opportunities/hour is workable locally, but does not yield 120 full refreshes/hour.** The shared budget and upstream generations reduced the observed rates to 48 Bazaar and 12 auction refreshes/hour. Auction data exceeded the three-minute freshness limit during waits, and the UI withheld comparisons. Do not weaken that limit or send price-based alerts from stale data to make the rate look successful.
3. **56 cleanups/day is too frequent for this allowance unless there is a concrete retention need.** One-page listings alone consume 34.72% of the monthly Class A allowance; 50/day consumes 31%. Daily cleanup uses 31 operations (0.62%). Every extra listing page increases these totals.
4. **An hourly cloud candidate still needs further sizing before activation.** At most four uploads/hour plus one daily listing is **3,007 Class A operations/month (60.14%)**, before other storage activity. This fits that single allowance but leaves limited room under the 65% slowdown threshold. It does not establish affordable database or transfer use. Hourly data becomes stale after three minutes, so fresh comparisons and price-based alert evaluation would be available only briefly following successful refreshes.
5. **Continuous 20-second Bazaar polling does not fit the measured response size.** Even with 16 conditional responses, the Bazaar page projected 28.74 GiB/month. Dividing 75% of 1 GiB by the observed average transfer rate gives only about **19 minutes/day** with no other egress or baseline included. This is an illustrative upper bound, not a safe usage grant. A substantially smaller response/delta design or a different serving arrangement is needed for continuous fresh browsing.
6. **Metadata deduplication helps, but cannot rescue the requested cloud workload by itself.** The trial already avoided 67 of the naive 80 possible publications (**83.75%**) by doing only due work. Of its remaining 13 versions, election checks still created new versions solely because their verification timestamp changed. After measurement, catalog/election identities were changed to content hashes and successful fee-verification times moved to shared coordination. Unchanged metadata now retains its blob; actual profile changes still republish derived snapshots and unavailable fee data still withholds recommendations. New tests verify this across a new collector instance. This fix was **not deployed and is not included in the measured sample**. The ten actual Bazaar/auction publications alone extrapolate to **44,640 uploads/month**, already 892.8% of the Class A allowance before metadata or cleanup.

The original desired $0 outcome is **not technically enforced on the billing-linked collector project**. Pausing prevents this scheduled workload, but retained images, storage, future authorized calls and other account activity can still accrue charges. No new charge amount is confirmed. The concrete billing-unlink/shutdown option and its retention/service effects remain in [ZERO-COST-AUDIT.md](ZERO-COST-AUDIT.md); unlinking billing or deleting retained resources was not authorized or performed. The local measurement required neither an invoice nor accepting possible cloud-trial network charges.
