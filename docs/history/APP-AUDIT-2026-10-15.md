## Implemented improvements

- **Public startup:** moved the authenticated workspace and Firestore initialization behind a lazy import. Authentication restoration still uses the existing observer. Signing in on a public item link does not load private code or read portfolios until a private view opens. A previously visited workspace stays mounted during item navigation to retain its private session cache. A failed module now shows an accessible error and reload action.
- **Market cache CPU and cancellation:** persistent public entries now enter the existing bounded memory cache. Timestamp headers allow cross-tab freshness checks without repeatedly decoding full-market JSON. Legacy headers are upgraded under the same Web Lock without changing sample times, read times, or expiry. Shared requests have independent subscribers: one cancellation cannot cancel another reader; the last departure aborts I/O. A completed response that pauses polling still delivers its book and error before future work stops. Corrupt cache envelopes recover safely.
- **Rendering:** reused number formatters, memoized portfolio totals and catalog filtering, and retained chart geometry across cursor movement. Every retained chart point and returned book level remains available. Display-only clocks stop while hidden and resume with the actual time; they do not change market scheduling or freshness thresholds.
- **Artwork:** added lossless WebP exports for the three active large PNG images. The build script verifies identical decoded RGBA pixels and dimensions. Original PNGs remain intact. CSS now requests the smaller exports; no crop, color, text, or illustration was altered.
- **Failure recovery:** Admin history failures expire after a one-minute cooldown, so reopening can recover without automatic polling. Collection errors now travel with selected-price replies and remain visible on item pages and portfolio valuations even when the prior sample is recent. Incomplete price batches remain explicitly stale and cannot create false chart drops.
- **Large portfolios:** deduplicated and split price requests into sequential batches of at most 100 distinct assets, matching the existing API limit. Previously, 101 assets produced an oversized rejected request. Each batch observes the preceding response's pause/backoff policy. Existing single-batch behavior is preserved.
- **Backend work:** concurrent selected-price reads share one in-flight snapshot/control read per collector instance. Notification evaluation reuses each portfolio document within its evaluation pass and omits an unchanged final ledger write. All immediate pre-send identity, cancellation, preference and ownership checks remain fresh. Completed legacy-position migrations now read the transaction marker before fetching three unnecessary documents.
- **Local proxy boundary:** reject non-loopback hosts, foreign browser origins and cross-site requests before spending the shared market budget. The fixed destination, credential stripping, selected-only route, deadline and server admission gates remain in force.

## Requests, database work and cost implications

| Scenario                                                            | Baseline                            | Current                                                                        | Evidence / scope                                                                    |
| ------------------------------------------------------------------- | ----------------------------------- | ------------------------------------------------------------------------------ | ----------------------------------------------------------------------------------- |

**Recurring-usage tradeoff, identified before activation:** large portfolios can increase recurring paid API usage. An uncached hourly read needs `ceil(distinct assets / 100)` selected-price GETs instead of the former single oversized rejection. Identical cached subsets can be reused; edits, expiry and eviction can cause misses. Portfolios of at most 100 distinct assets keep their existing one-batch behavior. Every request still needs server admission; pauses, expiry and stricter backoff stop subsequent network work. This change is now active following the separately authorized October 15 deployment.

Admin recovery can add a new read only when the user reopens a failed section after the cooldown; there is no background retry. First-time migrations still use four transaction reads but now have a marker-read round trip before the other three. The healthy selected-price response adds `,"error":null` (13 uncompressed JSON bytes); failures add their error text rather than hiding it. The constant mocked response in the browser benchmark intentionally isolates client performance and does not include this server-field change.

The separate offline paid-handler benchmark uses the real handler and Google REST adapter with a synthetic 1,000-item, 2,573,743 B snapshot, mocked Google storage, three warm-ups and 21 measured workloads per scenario. A warm 12-request workload performs one snapshot decode, 37 Firestore reads and 24 writes **including budget accounting**, with zero upstream calls. A cold-runtime workload performs 12 decodes and 48 reads; a 24-request concurrent workload shares one decode while retaining independent admissions. These are final-behavior measurements, not before/after savings or real charges. `reservedUsd` in the raw output is the application's estimate, not a Google bill.

## Flow and safeguard review

1. The public browser filters the existing supported catalog locally. Selection checks downloaded books and the hourly public response cache before issuing a selected-price GET. Item hashes remain shareable; invalid/excluded IDs do not request data. Both book sides, all returned levels and locally calculated volume bars remain visible on desktop and mobile.
2. The local server separates private emulator storage from public market reads. Shared mode forwards only validated selected reads to the fixed market service; offline mode reads SQLite. Browsing never calls an upstream collection endpoint.
3. The paid service admits requests against durable budget and expiry controls before serving published immutable snapshots. The existing scheduled collector alone fetches source market data. This audit did not alter its hourly schedule or budget reservation rules.
4. Private workspace reads remain scoped to the current user and session. Firestore ownership/schema rules, transactional mutations, tombstones and migration markers are retained. Public CacheStorage never receives credentials, portfolios, account settings or Admin responses. Admin caches are keyed by Firebase User object and only read the daily published report.
5. Notification configuration validates ownership, revisions and evidence; scheduled evaluation retains bounded batches, durable outbox transitions and checks immediately before sending. Local tests use mocks and do not send mail.
6. Visible-page scheduling still uses the hourly read window at two minutes past the hour, remembers failed attempts, obeys backoff and aborts on hide/unmount. Returning skips missed windows. Explicit failures remain stale; item display and stricter portfolio/notification freshness thresholds are unchanged. Displayed times remain fixed **EST (UTC−5) year-round**.
